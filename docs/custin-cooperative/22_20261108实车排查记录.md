## 2. 关键发现（含证据）

### 2.1 高德广播的真实结构（实车 logcat 抓取）

| KEY_TYPE | 出现场景 | 关键字段 | 频率 |
|---|---|---|---|
| **10001** | **仅导航中** | `CAR_DIRECTION`（航向）、`ICON`（转向）、`SEG_REMAIN_DIS`、`LIMITED_SPEED`、`CUR_ROAD_NAME`、`CAMERA_DIST/TYPE`、`ROAD_TYPE` | 事件驱动，数秒一条，有 4~5 秒空档 |
| 12205 | 常态（地图态也有） | **仅 `EXTRA_GEOLOCATION=0`（Integer，非定位对象）** | 高频（~1Hz） |
| 10019 | 常态 | `EXTRA_STATE=40`、`EXTRA_STATUS_DETAILS` | 偶发 |
| 13022 / 60021 | 偶发 | — | 低 |

**核心结论：高德在"纯地图、未导航"状态下不提供航向与导航数据。**
→ 想在地图态显示罗盘，只能用车机自身 GPS 或 C3（已明确不依赖 C3）。

### 2.2 高德会交替下发"全零"10001 帧

同一时间段内出现两类 10001：

```
[NAVI] navValid=true tbtIcon=5 tbtDist=103 dir=9 limit=30   ← 带引导数据
[NAVI] navValid=true tbtIcon=5 tbtDist=0   dir=9 limit=0    ← 全零刷新帧
```

原实现把 0 当有效值覆盖 → 仪表的**距离与限速牌反复归零再恢复**。
修复：零值视为"本次不更新"，保留上一帧（见 §3）。

### 2.3 仪表"圆圈"= 罗盘外圈被保活重发

```
[TBT] type=8 dir=30 reason=changed      ← 首次下发罗盘
[TBT] type=8 dir=30 reason=keepalive    ← 2 秒后
[TBT] type=8 dir=30 reason=keepalive    ← 4 秒
…（无限重复）
```

HSAE 仪表每收到一帧罗盘就重绘外圈 → 表现为"定时闪一下圆圈"。
修复：罗盘帧（`displayType=8`）不做保活重发，仅航向变化时下发。

### 2.4 导航中 `tbtTurnType` 被清零 → 罗盘/箭头交替

原解码逻辑：`ICON` 缺失时 `tbtTurnType` 取 0；而 `ClusterMapper` 判定
`tbtTurnType == 0 && carDirection 有效` 即进入罗盘模式。
既然高德部分 10001 帧不带 ICON，仪表就在箭头与罗盘之间来回跳。

修复：
- 解码器：导航中缺 ICON 时**保留上一转向图标**
- 映射器：罗盘仅在 **`!navValid`**（无导航数据）时出现

### 2.5 左右方向与高德相反

实车观察：高德地图显示右转时，仪表显示左转箭头。
处理：`ClusterMapper.mapTurnType` 左右成对镜像（ICON `3↔4`、`5/16↔6`、`7↔8`），
直行(65)/掉头(72)/目的地(112) 不变。

> ⚠️ 这一项只依据一次实车观察，若后续发现个别图标仍相反，可在
> `scripts/calibrate_cluster.sh --seq <码>` 逐码复核后微调。

### 2.6 百度与高德的仪表接入方式完全不同（Binder 实测）

10 分钟采集中的 Binder 事务（`binder_chain.txt`）：

```
1624(com.baidu.mapauto) -> 429(com.hsae.core)  call  size=104:0   ← 6 分钟内 5 次，间隔 70~100s
1624(com.baidu.mapauto) -> 429(com.hsae.core)  call  size=0:0     ← 10 次探测
```

- **百度地图是原生集成**：直接 Binder 调用 `com.hsae.core`，事件驱动推送。
- **高德进程没有任何直连 `com.hsae.core` 的调用**——高德的仪表投影由 **Reborn** 转译：
  `高德广播 → Reborn 解码 → HSAE Binder（IBINDER_NAVIGATION / IBINDER_VEHICLE）`。

这条差异解释了为什么"百度能做到的地图态罗盘，高德链路做不到"——数据源头不同。

### 2.7 `cameraID` 类型告警不是崩溃

logcat 中反复出现：

```
W/Bundle: Key cameraID expected String but value was a java.lang.Integer.
W/Bundle: java.lang.ClassCastException: Integer cannot be cast to String
W/Bundle:   at tech.touka.amapnavi.data.amap.AmapBroadcastDecoder.onReceive(...)
```

Android 4.4 的 `Bundle.getString()` **内部捕获该异常并返回 null**，
堆栈只是 `typeWarning` 打印用，**不会中断广播解析**。
仍做了容错（`safeStringExtra` + `readCameraId`），但**它不是"高德未连接"的原因**。

### 2.8 车机 GPS 可用

`dumpsys location` 显示高德自身及多个系统应用都在请求 `ACCURACY_FINE gps`，
说明 GPS 定位链路正常，可作为罗盘数据源（Reborn 原先未申请定位权限）。

## 7. 工程注意事项（踩坑记录）

1. **网络**：车机 IP 随热点变化（`192.168.8.201` → `192.168.144.253`），
   电脑换网段后需重新 `adb connect`；无线丢包高时 APK 传输会 `EOF` 中断，重试即可。
2. **车机 sh 极简**：无 `head/tail/awk/sed/wc`，但 `/system/bin/busybox` 全套可用。
3. **`id -u` 不可用**：toolbox 版 `id` 不支持 `-u`，用 `busybox id -u`。
4. **后台任务**：`adb shell`/`su -c` 退出会 SIGHUP 杀掉子进程，必须 `setsid`。
5. **脚本换行**：CRLF 会让 sh 报 `syntax error: '}' unexpected`，仓库已用 `.gitattributes` 固定 LF。
6. **车机时钟**：车机为 UTC（比本地少 8 小时），目录名由 PC 传入时间戳。
7. **安装命令**：Git Bash 下 `adb push` 远程路径会被 MSYS 改写，需 `MSYS_NO_PATHCONV=1`。
