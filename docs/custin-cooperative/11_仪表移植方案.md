# 11 原厂仪表（HSAE）移植方案

> 目标仓库：`AmapNavi-Reborn`
> 来源实现：`E:\code\adbridge-cluster`（`HsaeClusterClient`）
> 基线：2026-11-06 当前代码
> 原则：**只写仪表显示，不碰车控**；任何失败静默降级，绝不影响导航与变道主链路。

---

## 1. 目标与范围

### 1.1 要移植的能力

| 能力 | 仪表表现 | HSAE 事务 |
|---|---|---|
| TBT 转向诱导 | 大箭头 + 距路口米数 | `INavigation` transact 1 `cluTbtControl` |
| 道路限速 | 限速圆牌 | `INavigation` transact 5 `setNaviSpd` |
| 行程剩余 | 剩余公里 + 预计时间 | `INavigation` transact 6 `setNaviEstDist` |
| 文本行 | 路名 + 红绿灯倒计时 | `IVehicle` transact 46 `sendInfoToCluster(type=6)` |
| 退出清理 | 清空上述显示 | transact 1 (255) + transact 46 (空串) |

### 1.2 不做

- 不读车速/挡位/ACC（`adbridge-custin` 的 `HsaeVehicleClient` 只读接口不在本期）。
- 不做电子地平线/曲率写入。
- 不做任何车控写入。
- 不替代 C3 的 HUD/遥测链路。

## 3. 总体设计

### 3.1 新增包结构

```
tech.touka.amapnavi.cluster/
├── ClusterTransport.kt      // 接口：sendTbt/sendSpeed/sendEst/sendText/clear
├── HsaeClusterTransport.kt  // HSAE Binder 实现（反射 + Parcel）
├── ClusterFrame.kt          // 数据类：一帧要发的 4 类内容
├── ClusterMapper.kt         // 纯 Kotlin：NaviState -> ClusterFrame（可单测）
├── ClusterPublisher.kt      // 节流/去重/保活/超时清理/失败退避
└── ClusterSettings.kt       // 读取 UserSettingsRepository 的开关
```

### 3.2 数据流

```
AmapBroadcastDecoder → NaviState(StateFlow)
        │
        ▼
ClusterMapper.toFrame(navi)
        │
        ▼
ClusterPublisher（去重/节流/保活）
        │  worker 线程
        ▼
ClusterTransport → HSAE Binder → 原厂仪表
```

`RelayEngine` 内启动一个 `ClusterPublisher`，在 `scope` 中 collect `naviStateFlow`；
`RelayEngine.stop()` 时调用 `publisher.clear()` 并释放。

### 3.3 线程模型

- Binder `transact` 是同步调用，**不得在主线程**。
- `ClusterPublisher` 使用单线程 `Executor`；队列只保留每类通道的"最新值"，
  避免高频导航广播把队列撑爆。
- 每次调用有独立 try/catch；异常不向上抛。

## 4. 数据映射

### 4.1 TBT

- 输入：`tbtTurnType`（高德 ICON）+ `tbtDistance`（米）。
- 映射：**按语义映射，不要照抄 adbridge 的直连表**。

高德 ICON 语义（以原版 APK `convert_tbt_type` 与文档 14 为准）：

| ICON | 语义 | HSAE 显示码（待实车校验） |
|---:|---|---:|
| 1 | 直行 | 65 |
| 2 | 左转 | 66 |
| 3 | 右转 | 67 |
| 4 | 左前方/左分岔 | 68 |
| 5 | 右前方/右分岔 | 69 |
| 6 | 左后方 | 70 |
| 7 | 右后方 | 71 |
| 8 | 掉头 | 72 |
| 9/11/12 | 环岛 | 146 |
| 14 | 收费站 | 212 |
| 15/20 | 驶出匝道 | 176 |
| 其它 | 无效 | 255 |

> `adbridge-cluster` 把 ICON 2 当直行、3 当左转，与 APK 语义不符；
> 移植时以本表为准，实车再校准。

- 距离：直接写米数；超过 9999 截断。
- 发送条件：`icon` 或 `dist` 变化，或每 2s 保活；最小间隔 500ms。

### 4.2 限速

- 取 `roadSpeedLimit`；为 0 时回退 `cameraSpeedLimit`。
- **钳制到 20–150 km/h**（INavigation 服务端限幅）；0 表示清除圆牌。
- 每秒变化不得超过 20 km/h；超限时分多帧平滑逼近。
- 发送条件：值变化；最小间隔 1s。

### 4.3 行程剩余

- 输入：`routeRemainDistance`（米）、`routeRemainTime`（秒）。
- 格式：`km` + `h/min`；公里数取整。
- 发送条件：公里数或分钟数变化，或每 10s 保活。

### 4.4 文本行

- 内容：`[红灯 18s] <路名>` / `[绿灯 12s] <路名>` / `<路名>`。
- 路名优先 `nextRoadName`，为空回退 `currentRoadName`。
- 红绿灯：`trafficLightStatus` 1/3 → 红，2/4 → 绿；倒计时取
  `trafficLightSeconds`，`<0` 不显示。
- 长度：截断到 24 个字符，避免仪表溢出。
- 发送条件：路名或灯态变化；倒计时每秒更新；最小间隔 1s。

### 4.5 清理

触发任一条件即清空（transact 1 的 255 + transact 46 空串）：

- `navValid == false`；
- 连续 3s 无高德广播；
- 收到 `EXTRA_STATE == 9/0`（导航结束）；
- 仪表总开关关闭；
- `RelayEngine.stop()` / 服务销毁。

  - 总开关关闭：不调用 transport；
  - transport 抛异常：不崩溃、退避重试。

  - 10001 包内红绿灯字段；
  - 路名/路线剩余字段；

### 7.2 实车验收（40 号清单补充项）

1. 导航开始 → 仪表出现箭头/米数/限速/行程/路名。
2. 红绿灯路口 → 文本行出现 `[红灯 Ns]` 并逐秒递减。
3. 变道/转弯 → 箭头方向与高德一致。
4. 退出导航 → 仪表清空。
5. 关闭总开关 → 仪表恢复原厂显示。
6. 服务不存在/无权限 → App 不崩溃，设置页显示原因。
7. 连续 30 分钟无 ANR、无 Binder 异常刷屏。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 固件事务号/字段布局不同 | 集中配置表；每类写入独立 try/catch；失败只禁用该通道 |
| ServiceManager 反射被限制 | target 22 无 hidden API 限制；失败时禁用并显示"服务不可用" |
| 调用方权限不足 | 捕获 `SecurityException`；必要时评估系统应用/平台签名 |
| 与内置导航抢仪表 | 仅在高德导航有效时写入；退出即清空；实车确认无冲突 |
| 文本过长/编码 | 截断 24 字符；只用中文/数字/括号 |
| Binder 阻塞 | 单线程 worker + 只保留最新值 |
| 仪表写入影响驾驶 | 只写显示层，不写车控；总开关默认关闭直到验证 |

## 11. 附：与 adbridge-cluster 的差异处理

| 项 | adbridge-cluster | 本方案 |
|---|---|---|
| 架构 | 独立 App + 服务 | Reborn 内模块，随主服务生命周期 |
| 决策 | `decide()` 恒 KEEP | 不影响 Reborn 决策 |
| ICON 映射 | 直连表（语义有误） | 语义表 + 实车校准 |
| 文本行 | 直接写 | 同样写，但受开关与长度限制 |
| 清理 | 退出/销毁 | 增加 3s 超时与 `EXTRA_STATE` |
| 失败处理 | 吞异常 | 分通道禁用 + 状态上报 UI |

## 12. 与现有 adbridge 共存

车上当前运行的是“智驾数据桥·库斯途融合版”，可能已经在写仪表。

- **端口冲突**：Reborn 与 adbridge 都绑定车机本地 `7706`，同机不能同时运行。
- **仪表双写**：两个 App 同时 `transact` 会让仪表显示互相覆盖。
- **推荐**：二选一。
  - 保留 adbridge：先把 `clusterEnable=false`，再启用 Reborn 仪表；
  - 改用 Reborn：停用 adbridge，避免 7706 与仪表双写。
- 实车验证前，在设置页显示“仪表写入者”状态，便于确认没有双写。

## 13. 关联风险（非本方案范围，但必须知道）

| 项 | 现状 | 影响 |
|---|---|---|
| C3 `lane_runner` 频率 | 按 20Hz 设计，实车推理 554–806ms | 只能 1Hz；需降频/自适应，否则队列滞后 |
| 车道类别语义 | `CLASS_TO_SOLID` 未标定（APK 内无类名） | 标定完成前不得用 `leftLine/rightLine` 做实线阻断 |
| C3 `/lane.json` | 当前无该路由 | adbridge 的 LanePoller 会 404；需补路由或改走 UDP |

> 仪表移植只消费高德导航数据（TBT/限速/路名/红绿灯），**不依赖上述车道线能力**，
> 因此可以与 R-2 标定并行推进。
